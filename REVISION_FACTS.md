## TODO-01: how the reported metrics were computed
* Library: pyiqa 0.1.16 (`pip install pyiqa --no-deps` in the notebook), `create_metric('psnr' | 'ssim' | 'lpips')` with default options.
* PSNR: RGB, all three channels, data range 1, `10 log10(1/(MSE + 1e-8))`, no border crop.
* SSIM: Y channel of YIQ (0.299 R + 0.587 G + 0.114 B) scaled to [0, 255] and rounded, float64, Gaussian window 11 × 11 with σ = 1.5, valid filtering, no down-sampling, no border crop, C1 = (0.01·255)², C2 = (0.03·255)².
* LPIPS: AlexNet, v0.1.
* Inference (`KASIRNetInferencer.run_dataset_inference`): full-resolution forward pass, output clamped to [0, 1] and not quantised, ground truth resized to the input size when the sizes differ. **At most the first 256 sorted images of each test folder were evaluated** (`max_images=256`).
* Checkpoint selection during training (`OMSTrainer._validate_epoch`): mean PSNR on centre 256 × 256 crops of the GoPro test set, the DeRaindrop `test_b` set and the RESIDE-6K test set, i.e. on test images.

The revised code keeps the same metric function (`metrics.py`), evaluates every test image and selects the checkpoint on a split held out from the training pool.

## TODO-03: frozen networks in the released code
* `VGG19SemanticExtractor`, the perceptual-loss VGG-19 and the identity-loss ResNet-50 were all built with `weights=None`: **no ImageNet weights were loaded** by the released code. The identity-loss ResNet-50 also stayed in train mode (BatchNorm with batch statistics).
* `Loss.py` contained `ELRICLoss` from another project; the loss actually used is `OmniRestorationLoss` in the notebook.
* `Config.py` had batch size 64 and 3,000 epochs; the notebook trained in FP32 (no autocast), with `CosineAnnealingLR(T_max=3000)` stepped once per epoch.

Revised code: ImageNet `IMAGENET1K_V1` weights everywhere, frozen networks always in eval mode, paper hyper-parameters (batch 6, FP16, per-iteration cosine). The `audit` stage measures the distance between the VGG-19 weights stored in the submitted `best.pth` and the ImageNet weights (`vgg_is_imagenet`).

## TODO-05: SRB gate
`resonance_gate` ends with a Sigmoid and is not zero-initialised: on random features its output is 0.495 ± 0.45 at initialisation, so `A' = A(1 + G)` starts around 1.5 A. The gate multiplies the amplitude only and keeps the phase exactly (measured phase change of the gated spectrum: about 1e-8 rad); the complex 1 × 1 mixing that follows does change the phase (`spectral_srb_phase_and_gates` reports both per SRB on the trained model).

## TODO-15: loss weights actually used
The submitted notebook used `fft_weight = 1.0` (HYPERPARAMS) and `edge_weight = 1.0` (constructor default), not 0.5 / 0.5, and its SSIM term (pyiqa metric created without `as_loss=True`, evaluated under `torch.set_grad_enabled(False)`) contributed **no gradient**. ## Findings after the first G4 run (100 epochs, batch 64)

* **Rain100L benchmark source was Rain100H.** Kaggle `bshaurya/rain-dataset` (`rain-/norain-xxx.png`, 481 × 321) holds the Rain100H test pairs: mean input PSNR 12.13 dB, identical to `alicewen820/rain100h`, so the first run reported Rain100H twice (26.77 / 0.863). The genuine Rain100L test set is `adeshpal/rain-100l` (`Rain100L/{input,target}/<n>.png`, 480 × 320, the MPRNet/Restormer test layout, input 25.52 dB). Its clean images are crops of the same 100 backgrounds, so the leakage audit of the training pool is unchanged. Every real benchmark now has a fingerprint (number of pairs, mean input PSNR) checked during the audit; the wrong source stops the run (`input 11.61 dB; expected 25.52 dB`).
* **Köhler references are not aligned.** The 12 blurred images of each scene share one sharp reference and are offset from it by 2–10 px (phase correlation), so a perfectly deblurred image scores below the blurred input. This explains 19.35 dB (output) < 20.27 dB (input). Köhler is now scored after RealBlur-style registration (intensity scaling + ECC homography, valid region): e.g. blurred input 1_12 22.63 → 26.56 dB once registered.
* **Full-image inference is out of the training regime for several operators.** Measured on real images: the SRB gate input (mean of the un-normalised rFFT2 amplitude) is 2.3–3.1× larger on 480 × 640 – 760 × 670 images than on their 256 × 256 crops (≈ √(N/256²); 3.75× expected at 720 × 1280). The SRB complex 1 × 1 mixing equals, exactly (max error 4e-15), `a_r x + a_i Qx + b_r Rx + b_i QRx` with R the point reflection of the whole map and Q the quadrature transform; the anti-linear terms couple each position with the opposite one of the whole input. Chu et al. (TLC, ECCV 2022) document the same train/test gap of global operators (Restormer on GoPro: 32.92 → 33.57 dB with local statistics at test time). Hence the train-consistent tiled protocol, selected on held-out validation pairs (`Config.INFERENCE_PROTOCOL = 'auto'`).
* **Optimisation budget.** At batch 64, 100 epochs = 35,700 updates at learning rate 1e-4 (the batch-6 value), ~10× fewer updates than the batch-6 setting. The final model continues the 100-epoch model with a 200-epoch cosine cycle at 3e-4 (warm-up 1,500 iterations); the 100-epoch model stays the reference of every ablation table.
* **Unreliable submitted figures.** The submitted Rain100L 40.10, Köhler 31.99 and SIDD 41.94 are not reproducible by construction (test images in training, no SIDD data). SIDD 41.94 is above published single-task SIDD results (NAFNet 40.30 dB), and GoPro 33.61 for an all-in-one model would be on par with single-task state of the art (NAFNet 33.69, Restormer + TLC 33.57); all-in-one models in the five-task setting (IDR, AdaIR) report GoPro clearly below single-task models (check the exact values in their tables before quoting them).

## Model and loss review (second revision pass)

Fixed (no parameter changes; a submitted checkpoint still loads with `strict=True` and gives the same output, within 2.4e-7, on inputs whose sides are multiples of 128):

* **Identity loss used batch statistics.** The ResNet-50 of `L_id` was built in training mode and never switched: its 53 BatchNorm layers normalised prediction and target by their own batch statistics, and its running statistics drifted. It is now in eval mode from construction on, and so is every frozen extractor of the SIM.
* **Loss weights did not set the balance of the loss.** With the raw terms the gradient with respect to the restored image came 63 % from `L_id` and 32 % from `L_perc`, but only 1 % from `L_pix`, whose weight is 5. The `L_id` direction is almost orthogonal to the error (cosine 0.00–0.01). On real Rain100H / Rain100L / RealBlur / LOL / composite pairs, the weights now act on scale-calibrated terms (`Config.LOSS_CALIBRATION`): s_k = g_pix / g_k, measured once per training pool at prediction = degraded input on the held-out validation patches and shared by every run. The paper weights 5 / 0.5 / 1 / 1 / 1 / 0.5 are then the gradient shares, i.e. 56 / 6 / 11 / 11 / 11 / 6 %.
* **FFT term scale.** With the unnormalised rFFT its value and gradient grew with the patch side (gradient 26× the pixel gradient at 256 px). It now uses the orthonormal FFT. The `+1e-6` added to both amplitudes cancelled out and is removed.
* **Output clamp during training.** `clamp(0, 1)` zeroed the gradient of every pixel overshooting [0, 1]. It is now applied only in eval mode, so inference is unchanged.
* **Internal SCWAM padding at full resolution.** Inputs were padded to a multiple of 16, but a window of 8 at 1/16 resolution needs a multiple of 128. The SCWAM layers then zero-padded internally *before* LayerNorm, so padded tokens became the LayerNorm bias, and the cyclic shift wrapped real border tokens onto padding. Inputs are now replicate-padded to a multiple of `window_size × 2^num_scales` = 128. Training patches (256) and the 256 / 384 tiles were already multiples.
* **Wasted computation.** The SFT 1 × 1 convolutions ran on the descriptor broadcast to H × W (4 % of the FLOPs) and now run once on the 1 × 1 descriptor; the Meshgrid embedding is computed once per batch instead of per sample. Both give identical results.

Not changed (architecture), to be described accurately in the paper:

* The SRB `freq_conv` bias adds the same value to every frequency bin. In image space this is an input-independent pattern on row 0 (an impulse at pixel (0, 0) plus a 1/n tail along the first row) in each of the 9 SRBs. The sin² tile window is zero at tile borders, which removes it from tiled outputs.
* Each decoder stage receives the VGG features of the next coarser scale (e.g. decoder1 at H/2 receives pool1 features at H/4), up-sampled bilinearly inside the SIM.
* There is one SCWAM layer per scale, always shifted by 4, so there is no alternation between regular and shifted windows as in Swin. The shift moves the window grid and adds wrap-around windows at the borders.
* The SSIM term is computed on luminance only (Y of YIQ), like the metric.
